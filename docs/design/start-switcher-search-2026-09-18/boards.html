1 · The start page rethought from first principles · a Fluent start window, not a card

Before a project is open the window has one job: get the estimator into the right job in one action. Three ways in, in the order they happen: continue yesterday's job (nearly every launch), start a bid from a drawing set someone handed over, reopen an older job. Today's screen is a 600px card floating in the void, the action buttons and the recents fight for the same column, and three text links (rename · forget · remove data) sit on every recent row. The rethink is the Fluent start-window shape (Visual Studio, Terminal): the recents on the left, with a filter, one row per job and a right-click for the rest; the ways in on the right as cards, with the primary one in the accent; drop a PDF or a folder anywhere on the window; Enter reopens the last job; Ctrl+O browses. The mark, the version and the update state live in the footer, where a start window keeps them.

2 · The project switcher a first-class flyout, not a content-heavy dropdown

Today the project name in the title bar opens a menu that lists recent projects as menu items with full paths under them, then "Open another project…" and "More… every project, in the prompt". It reads as a menu that is carrying a page's worth of content. A switch of job deserves the same surface a project gets on the start page: a Flyout that opens with the current job as its header (name, folder, and what you can do to it), a filter, the recent jobs as rows with when they were last opened, and the two ways out in a footer bar. Choosing a job still opens it in a new window, because a window is a job; the row's trailing glyph says so on hover instead of a sentence at the bottom.

3 · The search pane usability, and highlights that ask which scope

Two problems. The functional one you named: Highlight puts shapes into whatever scope happens to be active, and with no takeoff scope in hand it still picks one. A highlight is a markup that belongs to a scope, so the pane must know which before it makes one. The fix is a "Highlight into" chooser at the head of the results, empty by default: while it is empty the highlight buttons are disabled, and pressing one opens the chooser as a question rather than doing nothing. The choice is remembered for the pane, and it never changes the takeoff scope in the dock. The usability ones: the reach was a full-width select reading "the whole project"; groups were file names; hit rows were "p6 + snippet" with an icon button on each; the footer said "Matches appear as you type". Now the reach is a SelectorBar, groups are sheet numbers with their titles, hits are the snippet with the match in the accent and a page tag, Enter walks the hits, and the footer counts matches, sheets and coverage.

The gate. No scope chosen → every highlight control is disabled and the "All" button reads as such. Pressing one opens the question (B). Choosing sets the pane's scope for the session; it is not the dock's active scope and does not become it.

The chooser lists the round's scopes with their colour and product, and offers "New scope for these…" for a search that is itself a scope ("every note that says acoustic"). Escape backs out with nothing made.

A hit that is highlighted shows the filled glyph, the group counts them, and the footer says which scope got them. Pressing the filled glyph removes that highlight; the pane never leaves a highlight it cannot show you.

Reach is a SelectorBar under the field: This sheet · Document · Folder · Project. One tap, no dropdown.

Groups are sheets (number, then title) for the open document; other documents group under the file name and say how many of their hits can be shown on screen. Hits on a page that has readable paragraphs get a ¶ tag; elsewhere just the snippet.

Enter walks the hits and the sheet follows; Shift+Enter walks back. The footer states matches, sheets, coverage, and the keys.

4 · Settings, second pass what the screenshot showed, and the fix

Built as drawn, the page failed on a real 1920px window: the column sat in the corner with two thirds of the window empty, the rows were hairlines in a void with nothing to hold them, descriptions were cut mid-sentence because one line at 760px is not enough for these sentences, and a toggle with no On/Off word is a shape, not a setting. The fix keeps everything that was right (one page, no rail, eight runs, the family drawn, Default inline, About last) and changes the frame: a centred 920px column, each run as a Fluent SettingsCard group — one raised card, rows divided by hairlines inside it — 56px rows with two-line descriptions allowed, On / Off beside every switch, the changed row's 3px accent bar on the card edge and a reset glyph, and the family's children on the card's lower fill with the connector.
