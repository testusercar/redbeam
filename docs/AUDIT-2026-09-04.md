# Functionality audit — 2026-09-04

Aaron's bug list, what each turned out to be, what was done, and what the rest
of the application does when driven. Run alongside the Fluent gap passes
(`FLUENT-GAPS.md`); nothing here restyles anything. Where the two overlap the
register's entry is named.

Verification: `cargo test` (110), `npm run typecheck`, `npx vitest run`
(97 files), `npm run test:mcp` (21) all green at the end of the pass. Behaviour
was exercised in the browser build on a private dev server (`harness-5197`)
with synthetic wheel, pointer and keyboard events against `window.__redbeam`,
and the exported PDF was rasterised and looked at. The desktop-only paths
(headless indexing of real files, sheet snapshots, the second-window store
fix) are covered by unit tests and the Rust suite; they still want one run in
the real app on a real project, noted under *Open*.

## Everything else that was driven

Pass means it behaved as designed under synthetic input in the browser build.

- **Pan tool:** click-select, marquee (Shift-drag) selects fully enclosed markups incl. dimensions, Delete removes the selection as ONE undo step ("delete 2 markups"), Ctrl+Z restores, Ctrl+Y redoes. Pass. (Pointer capture on the pan and rectangle paths is now tolerant of a pointer the browser does not consider active; before, a refused capture aborted the handler.)
- **Drawing:** Escape cancels a polygon in progress; Enter commits; right-click backs out; count commits per click. Pass.
- **Calibration:** `k` + two clicks brings up "The line you drew is N pt. How long is it really?" with a feet field; Escape cancels. Pass.
- **Scale region:** Shift+K + two clicks records the box; the picker did not surface any text in the dock under synthetic input. Listed under *Open* to confirm in the real app.
- **Markup menu:** right-click on a markup or a dimension opens it. It closed only on a click on its scrim; **Escape now closes it too** (fixed here).
- **Estimates panel:** New estimate → name → Enter; open; Add scope → name → Enter opens the scope with Take off; the round menu (rename, duplicate, exports, delete) works; breadcrumbs navigate. Pass.
- **Palette:** Ctrl+K opens; typing "export estimate" finds the new command. Pass.
- **Panes:** Files (tree), Contents (75 rows on the sample), Thumbnails (grid), Search (Ctrl+F focuses the field; reports LIKE fallback in the browser build honestly). Pass.
- **Settings:** Ctrl+, opens the full view; "Scroll wheel zooms" shows Off. Ctrl+, again closes it only once focus has left a text field (the shortcut survives text entry as an opener but the field keeps the second press). Minor; noted below.
- **Zoom keys:** Ctrl+0 fits the page, Ctrl+wheel zooms about the cursor. Pass.

## Live test of the installed 0.2.0 build — 2026-09-05

The ARM64 installer, launched from the Start menu with no arguments (the app
reopened its remembered project on its own), driven through the bridge and
the real keyboard on the Barclays case study (693 documents).

**Worked end to end:** open the case study from the switcher; open the
architectural set from the Files tree; `:40` in the palette to A-413A; Set
scale → 1/8″ from the palette; New round → Add scope → product → counts →
Panel W 4 ft → Panel L 8 ft, all in the palette; an area drawn into the
scope (bridge) with the layout preview, 4,424.1 SF / 268.8 LF and 160 panels
on the Parts page; Commit; the Markups page by sheet; Save report through
the native Save As (the file carries the round and scope); a context window
on the same project; the round menu; every setting as a switch, flipping and
staying; the store refusing nothing it should have allowed.

**Defects found, and what was done:**

1. **A folder inside a project opened as its own project** with a new
   `redbeam.db` beside the drawings. The bridge's open-project handler set
   the workspace path straight from the event instead of going through
   `project.open`, so the root resolver never ran. Fixed in `App.tsx`; the
   stray database was removed after the app closed. The picker's own path
   was never affected.
2. **Escape did nothing in the palette** in the installed app — neither
   clearing the query nor closing — and after a configure chain the field
   had lost focus (the `Next` flow replaces a chip without changing the
   count the refocus effect watched). Two changes in `CommandPalette.tsx`:
   the field refocuses on any chip change, and Escape now cancels the
   palette outright (Backspace on an empty field is the way back a step).
   Whether the webview delivers Escape at all in the installed build still
   wants one keypress in the next build.
3. **"This sheet has no scale" showed with no sheet open**, on the start of
   every project. Guarded on an open document in `Workspace.tsx`.
4. **The indexer's progress was a spinner, and it painted over the expanded
   Search tab.** Now determinate: a ring behind the collapsed icon, the count
   and a foot bar on the expanded tab, and a bar plus the numbers in the
   Search pane's footer. Harness: `?harness=shell&state=indexing`.

**Open, not fixed here:**

- The round page's markup counts and totals read 0 after a project reopen
  until the sheet carrying the markups is visited; they are counted from
  loaded pages, not the store.
- The window's undo indicator did not pick up a bridge write (the store's
  undo log had it) until a later action.
- The per-project connection map keeps a switched-away project's database
  open for the life of the process, so its files cannot be removed while
  the app runs.
- A black band paints over the Files row beneath the active document for a
  moment after a sheet renders (seen twice, not reproduced on demand).
