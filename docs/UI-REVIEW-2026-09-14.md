## 2. Cross-cutting systems

These are the twelve root causes. Fixing each one closes a large fraction of the entries in section 3.

### 2.1 One sheet-identity parser
**Problem.** The app never extracts sheet number, title or issue. It shows raw filenames, truncated at whichever end the container happens to cut, so ten tree rows read `A-46x - ENLARGED-BASE-ELE…`, two tabs differ by one letter, Pinned rows are unreadable, the prompt shows an 80-character upper-case filename, and the current sheet's markup group is labelled `Page 1 · Page 1`. The revision lives only as filename text (`REV.3`, `BULL.10 6-26-26`) and is the first thing truncated away. The same document has at least six different on-screen names.
**Proposal.** One parser (filename pattern, then title block, then user override) producing `number · short title · issue · page`. Every list, tab, breadcrumb, group header, prompt row and export uses it: primary `A-351B`, secondary `Sector B RCP · Bull.10`, full filename in a tooltip. A truncation policy goes with it: never cut the distinguishing token, never ellipsise inside an editable field, always provide a tooltip.
**Raised by.** All eight.

### 2.2 One number and dimension formatter
**Problem.** `1,386.4` beside `1260.5`; `10' 0"` beside `1'-0"` beside `3'-9"` beside `4"`; 0.1 SF precision on a 1/4" drawing; units set smaller than the number and in a lower-contrast grey.
**Proposal.** One formatter: thousands separators, a configurable decimal rule (default 1 decimal for SF/LF, 0 for EA), one feet-inch style (`10'-0"`), tabular figures, unit at the number's cap height in secondary text. Export rounds the same way the screen does. Units and precision become a setting.
**Raised by.** Est, Mgmt, Jr, Des, WinUI, A11y, BB, PM.

### 2.3 Typography: Segoe UI Variable, tabular figures, no monospace for prose
**Problem.** Monospace is used for paths, hex colours, prompt subtitles, all numbers, KPIs, counts, zoom and scale. Lower-case monospace descriptions ("freeze the count as it stands") make the product read as a terminal. Base text is 11–13 px; nothing above 15 px except one heading. Type scale has an off-ramp 28 px display size.
**Proposal.** `Segoe UI Variable Text` throughout with `font-variant-numeric: tabular-nums` for numeric cells. Monospace only for literal paths and the `redbeam.db` code span. Ramp: Caption 12 / Body 14 / Body Strong 14 / Subtitle 20 semibold for KPIs. Base 14 px, captions never below 12 px, honour Windows text scaling (rem).
**Raised by.** Est, Mgmt, Des, WinUI, A11y.

### 2.4 One accent ramp, and the brand-red question
**Problem.** The brand is red; every interactive surface (primary buttons, Take off, tab underline, tree selection bar, focus ring, toggles, badge numerals) is a hard-coded light blue (≈ #4CC2FF). The red RB mark appears only on the start card; the title bar shows a provisional orange icon. Scope colours may also be red, so red currently means brand, danger and "a scope".
**Proposal.** One accent through a full Fluent ramp (default / secondary / tertiary / disabled / text-on-accent). The project's `.pen` comps already decide red for brand, nav and focus; adopt it, verify white-on-red ≥ 4.5:1, and purge the blue. Reserve `--danger` and `--warning` tokens separately. Scope palette excludes the accent and the danger hue. One icon asset app-wide. See section 4.1 for the Mica / system-accent disagreement.
**Raised by.** Est, Mgmt, Des, WinUI, A11y.

### 2.5 Contrast tokens and opaque surfaces
**Problem.** Measured: Setup field key labels 3.16:1, `Find a setting` placeholder 2.40:1, count badges 3.43:1, section counts 3.58:1, table headers 4.01:1, filter placeholder 4.01:1, prompt subtitles 4.49:1 (3.49:1 on the selected row), menu header 3.70:1, secondary-button borders 1.70:1, text-field boundaries 1.36:1. The prompt, both context menus and the floating toolbar are translucent, so their ratios drift with whatever part of the drawing is beneath (toolbar text drops to 4.0:1 over white paper).
**Proposal.** Three text tokens (`--text-1` ≈ #F1F3F4, `--text-2` ≈ #B8BDC3, `--text-3` ≈ #93979C, the last for placeholders/disabled only) and three fills; component boundaries ≥ 3:1. Opaque panel/menu/toolbar surfaces, or opaque whenever `prefers-reduced-transparency` or high contrast is on. Acrylic only over app chrome, never over the sheet.
**Raised by.** A11y, WinUI, Des.

### 2.6 One selection idiom (lists, strips, canvas)
**Problem.** "Selected" is drawn six ways: left accent bar (rail tab, prompt row, settings nav), bottom underline (doc tab, toolbar tool), raised fill only (tree focus), scope-coloured left bar and tinted header (scope page), raised tile plus underline (toolbar). In the tree two rows read as selected at once. On the canvas the selected markup is a 1 px lighter outline in the scope's own colour with 5 px white handles that look like column symbols; nobody found it without zooming.
**Proposal.** Lists: selection = left bar + subtle fill; hover = lighter fill that clears on pointer-leave; keyboard focus = 2 px ring, never a fill. Tab and tool strips: one indicator (WinUI toggle fill or a single underline), never both. Canvas: dual-stroke outline (white + black or marching ants) independent of scope colour, 8 px handles with a contrasting border, vertex handles on hover, plus a readout pill. Scope colour tints nothing except the dot and the markup fill.
**Raised by.** All eight.

### 2.7 Row heights, control heights and targets on the 8 px grid
**Problem.** Row heights of 18, 20, 23, 24, 27, 31, 36, 40 and 46 px across tree, Pinned, Parts, menus, buttons, prompt rows. Menu rows 22 px, markup rows 18 px, tool buttons 23 px, tree expanders ~17×15 px hit area, inline text links ~13 px — all under the 24 px minimum.
**Proposal.** Three row tokens (24 dense / 32 default / 40–48 two-line), 32 px controls, 36 px menu items with icons, 32×32 icon buttons, expander hit target the full row height. Four chevron weights become one 16 px Fluent glyph.
**Raised by.** Des, WinUI, A11y.

### 2.8 Lifecycle and provenance vocabulary
**Problem.** "Commit — freeze the count as it stands", "Not committed.", "unverified" in yellow on every part line, "Archive", "Remove from estimate", "forget", "remove data", "Duplicate — the specification, not the takeoff". Nobody can say which number is the bid number, whether commit is reversible, what verified means, or whether Archive and Remove are the same action. Nothing records who did anything or when; there is no user identity, no history, no last-committed value to compare against.
**Proposal.** Three scope states with fixed words: **Draft → Locked → Archived** ("Lock quantities" replaces Commit; markups stay editable and move the scope to "Changed since lock +12.4 SF"). Parts carry a separate **Computed / Verified** state with who/when, lost automatically on any Setup or markup change. **Delete** is a separate, confirmed, permanent action. Author initials (from the Windows account by default) and timestamps on markups, locks, calibrations and verifications; a History list of locks with values and deltas. Names for the levels: Estimate (round) › Scope; never scope-inside-scope.
**Raised by.** Est, Mgmt, Jr, Des, WinUI, BB, PM.

### 2.9 Glossary and voice
**Problem.** "Take off" / "Takeoff" / "takeoff"; "drawing set" vs "project folder" vs "folder by path"; "kind" vs "type"; "the prompt (~)" vs Ctrl+K; "Unset"; "The drawing"; "needs a choice"; "step 1"; "each measure"; lowercase option values ("full", "never") next to sentence case; ellipsis used inconsistently; chatty lower-case subtitles that change voice row to row; hex codes shown to estimators.
**Proposal.** A 20-term glossary enforced in code review: noun "takeoff", verb "Take off"; "Estimate" and "Scope"; "PDF markup" (the architect's) vs "area/length/count" (ours); "Lock"; "Archive"; "Delete". Sentence case everywhere; ellipsis only when more input is needed before anything happens; verb-first titles with one-line factual subtitles ≤ 45 characters; no internal state words in the UI. Spelling stays British/Canadian consistently (section 4.4).
**Raised by.** Est, Mgmt, Jr, Des, WinUI, BB.

### 2.10 Active scope as a single source of truth
**Problem.** Opening the CL04 hub, following "Go to it" to a CL04 markup and selecting it leaves the toolbar chip on TROUGHS; opening the scope page from a right-click flips it to CL04. "Trace the region here" and "Convert polygon … to an area" go into an unnamed scope. Pressing Take off at the wrong moment draws baffle areas into the planks scope, silently — every persona who does takeoff called this the most common estimator error.
**Proposal.** One "current scope" state. Opening a hub, selecting a markup, opening a scope page or picking from the chip all set it. The chip reads "Drawing into: CL04" and is a SplitButton; every context-menu action that books a measurement names the target scope in its label; the in-progress polygon, a canvas border and the cursor tag carry the scope colour and a 2-letter tag.
**Raised by.** Est, Mgmt, Jr, Des, WinUI, A11y, BB, PM.

### 2.11 Labelled controls, tooltips and shortcuts everywhere
**Problem.** Seven unlabelled tool icons with non-standard metaphors (cart? trough? ⊘ next to ✕), no tooltips visible, no shortcut letters anywhere, three unlabelled rail tabs, unlabelled `+`, unlabelled open-externally glyph, an unexplained count on every list, no menu accelerators, no Ctrl+K hint anywhere in the UI, and the only keyboard legend is the smallest text on screen.
**Proposal.** Every icon-only control gets a tooltip with name and shortcut; the takeoff tools get text labels beneath icons at widths where they fit; every hub row and menu item shows its accelerator; a visible "Ctrl+K" hint in the title/status bar; a `?` shortcut sheet; a rebinding page in Settings.
**Raised by.** All eight.

### 2.12 Empty, loading, disabled and destructive states
**Problem.** The canvas is a black void with no instruction. The dock shows 35 % zoom of nothing, page arrows enabled at 1/1, "Unset" scale and an enabled Take off with no sheet open. "Reading the folder…" persists beside a fully painted tree; totals appear only once a sheet is open. Destructive actions ("remove data", "Remove from estimate", "Convert all 101 PDF markups", "Reset all", the toolbar ✕) look identical to safe ones and show no confirmation cue.
**Proposal.** An empty-state component (glyph, one line, two ghost actions); a loading component (progress count, skeleton rows, never blank numbers); disabled tokens for anything with nothing to act on; a destructive-action idiom (behind a "…" menu, danger colour, ellipsis, ContentDialog naming the path and counts, undo toast where reversible).
**Raised by.** Est, Mgmt, Jr, Des, WinUI, A11y, BB, PM.

## 3. Proposed changes by surface

Entry format: **Change.** Why. — *severity* [personas].

### 3.1 Start screen (d1, d2)

1. **Replace "Open a drawing set…" / "Open a project folder…" / "Open a folder by path instead" / "Browse…" with one primary "Open a folder of drawings…".** Four routes to one action, and no user knows the difference between a set and a project folder. If two paths genuinely differ, say so in a sub-caption on each. — *major* [Est, Mgmt, Jr, Des, WinUI, BB]
2. **Move "rename / forget / remove data" into a per-row "…" menu: "Rename (F2)", "Remove from list", separator, red "Delete takeoff data…".** The destructive link is styled identically to Rename, one slip away; the confirm dialog must name the folder, the scopes/markups inside, and that drawings are untouched. — *blocker* (Jr) [Est, Mgmt, Jr, Des, WinUI, A11y, BB, PM]
3. **Collapse "Open" and "Create & open" into one "Open"; resolve the path live and show "Found redbeam.db" or "No takeoff here yet — REDBEAM will create redbeam.db in this folder".** The user should never have to know whether a database exists; disable the button when the folder does not exist. — *major* [Est, Mgmt, Jr, PM]
4. **Add a "New project…" flow that asks for name, job number, client and bid due date, and show job number and client on Recent rows.** Naming today is whatever the folder was called; job numbers are how bids are found and audited. — *paper cut* (data-model gap) [Mgmt, PM]
5. **Never ellipsise inside the editable path field; scroll it, show the tail by default, echo the resolved full path below.** The user is about to act on a path whose end is hidden; an ellipsis inside an input also reads as read-only. — *major* [Est, Mgmt, Jr, A11y, PM]

## 4. Disagreements and judgement calls

### 4.1 Mica and the system accent (WinUI) vs OLED black and brand red (Des, Mgmt, Est)
WinUI: Windows 11 apps sit on Mica with layered panes and either bind to the user's system accent or declare one app accent through the full Fluent ramp; flat #202020 reads as unfinished.
Des/Mgmt/Est: the `.pen` comps chose an OLED palette with red for brand, nav and focus; two accents already look like two products, and a third (the user's system colour) would vary per machine.
**Recommendation.** Keep the flat OLED ground (Mica over near-black is imperceptible and costs WebView2 transparency risk). Adopt brand red as the single accent through a generated ramp, verify white-on-red ≥ 4.5:1 for text-on-accent (otherwise use a red-tinted focus/selection with neutral high-contrast buttons), and purge the blue. Take WinUI's control anatomy (32 px controls, InfoBar, SplitButton, TabView shapes, overlay scrollbars) without Mica.

### 4.2 Bluebeam parity (BB) vs simplicity (Mgmt, Jr)
BB: a project-wide Markups List with custom columns, Tool Chest presets, layer visibility, split view, VisualSearch counts and .btx/.bcx import are the price of leaving Revu.
Mgmt/Jr: one Open button, sixteen settings, fewer ways to do a thing; every added panel is another thing a new hire must be taught.
**Recommendation.** Build the two that are also the deliverable and the audit trail: the Markups List (table, totals, export) and cross-project scope presets. Add the PDF-markups dim/hide toggle because both sides need it. Defer split view, user-defined formula fields and find-similar counting to a later round; keep Settings small but add the Units, Import and Appearance groups.

### 4.3 Floating toolbar vs docked bar
Est/BB/Des: a floating bar covers the title strip and grid bubbles and reflows; dock it or auto-hide it.
WinUI: a floating CommandBar is a legitimate Windows 11 pattern (Photos), and the design intent is "dock rests until Take off".
**Recommendation.** Keep it floating this round: opaque, fixed group widths, a fit-to-page inset so it never covers the sheet after a fit, shadow + stroke so it reads as a layer, and an overflow menu at narrow widths. Add "dock to top/bottom" as an Appearance setting later rather than redesigning the shell now.

### 4.4 Spelling and locale
Est: bidding a Manhattan hospital in SF and LF, "Colour" and "centre" look foreign; pick US spelling.
Everyone else uses the British spellings without comment; the company is Canadian and its projects (Toronto, Vancouver, NYC) span both.
**Recommendation.** Keep British/Canadian spelling consistently; units are data, not locale. Do not mix. Avoid the two words that grate ("Colour…" in the hub becomes a swatch + name; "centre to centre" becomes "o.c.").

### 4.5 What to call "Commit"
Mgmt/Jr/BB: "Lock quantities" — says it stops the number moving and implies it can be unlocked.
Est: "Snapshot" — implies the live number keeps moving and the snapshot is what exports.
PM: the name matters less than history with values and deltas.
**Recommendation.** "Lock" as the verb and Draft / Locked / Archived as the states; markups stay editable and the scope shows "Changed since lock +12.4 SF"; every lock is a stored snapshot with author, time and note, so the PM's history comes free. Exports use the locked value by default and say so.

### 4.6 Scope page: tabs or accordions
BB: real tabs, with Markups pinnable at the top because it is what he looks at most.
Des/WinUI/Est/Jr: accordions with sticky headers and a jump bar; the tabs are lying today.
**Recommendation.** Accordions plus a scroll-spy jump bar, collapse state remembered per user. BB's "always visible markups" need is met by the project-wide Markups List (3.3.18), not by the scope page.

### 4.7 Recent-path truncation
Des/WinUI: end-ellipsis, one line, tooltip — the standard list idiom.
Est/Jr/PM/BB: keep the tail; the folder name is the only thing that distinguishes Bid from Addendum 2.
**Recommendation.** Keep the tail (start- or computed middle-ellipsis), full path in tooltip, one line. The users are right about which part matters.

### 4.8 Timestamps
Est: always absolute with year.
Mgmt/Des/WinUI: relative under 7 days, then absolute.
**Recommendation.** Relative under 7 days with the absolute in a tooltip; absolute with year beyond. Add PM's "last locked" stamp as a second column.

### 4.9 Command prompt as the main control surface (design intent) vs menus and shortcuts (Jr, BB)
Jr: nothing advertises Ctrl+K; mouse users never find the hub.
BB: a palette with no accelerators is slower than a toolbar.
**Recommendation.** Keep Ctrl+K primary, but advertise it (title/status bar hint, empty state), mirror every hub action into the scope "…" menu and the context menus, and show accelerators on every row.

### 4.10 Start screen: card or page
Des: the card can stay if anchored, sized and given states.
Mgmt/WinUI: a page with wordmark, wide recents and a right-hand action column.
**Recommendation.** A page. It also resolves the 4K void, the missing version/footer and the Recent list's growth to 40 rows.

### 4.11 Canvas selection colour
Est/Mgmt: outline and handles in the scope colour so the user learns the colour.
A11y/WinUI/BB: an outline independent of scope colour (dual-stroke or marching ants) so it reads on any fill.
**Recommendation.** Independent dual-stroke outline; handles and the readout pill carry the scope colour and tag.

### 4.12 Second "Add scope" position
Jr: keep the bottom one, where the new row appears.
Everyone else: keep the header one.
**Recommendation.** Header button; a ghost "+ Add scope" row at the end of the list only when the list is long.

## 6. Things the reviewers got wrong or could not know

- **The context menu open in d9 and d11** was left open by the screenshot driver, which changed the sidebar and activated the tool through the bridge without a pointer-down that would have light-dismissed it. Dismiss-on-tool-change (3.7.9) is still worth doing, but it is not the "state leakage" bug several reviewers rated major; it is downgraded to a paper cut.
- **The orange title-bar icon** is a known provisional placeholder (PIL-drawn during the control-surface work). The finding that one mark must be used everywhere stands; the "two app icons" observation is not news.
- **`1" = 3'-9"` on A-351B is real calibration data** entered on that sheet by two-point calibration, not an auto-detection error or a rendering bug — REDBEAM never auto-sets scale. What the reviewers could not see is the source. The finding that survives is the missing provenance and the missing warning when a calibrated ratio does not snap to a standard scale (3.11.1), not "the app got the scale wrong".
- **"Reading the folder…" in d3** is a moment-in-time capture; d4 shows the finished "90 documents". The transition should be honest (progress count), but the status is not stuck.
- **Totals absent in d3 and present in d4** is most likely load order at capture time rather than a rule that totals require an open sheet. Verify; the "always show, skeleton while computing" fix stands either way.
- **The highlighted A-764 row in d6** is plausibly keyboard focus left by the driver's navigation rather than a stuck hover. The design fix (focus = ring, never a fill) still applies.
- **The blue ring on the rail search icon in d4** is probably the same driver-focus artefact.
